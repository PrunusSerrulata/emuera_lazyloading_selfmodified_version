新增命令：CALLSTR, JUMPSTR, TRYCALLSTR, TRYJUMPSTR, TRYCCALLSTR, TRYCJUMPSTR
见下文。

修复 XML_ADDNODE 在匹配多个节点时只插入最后一次的 Bug
	在 .NET 的 XmlDocument 体系中，一个 XmlNode 实例只能拥有一个父节点。在旧代码中，当 `doSetAll` 为真且匹配到多个目标节点时，循环使用的是同一个 newChild 实例。这导致该节点在 DOM 树中不断被移动，最终只有最后一个目标节点成功添加了该子节点/属性。
	修复：
	引入了本地函数 `GetNewChild()`。
	- 对于节点 (Node) 操作，使用 `doc.ImportNode(sourceNodeForCopy, true)` 每次生成一个带有正确 OwnerDocument 的深拷贝克隆节点。
	- 对于属性 (Attribute) 操作，每次循环都调用 `doc.CreateAttribute` 创建全新的属性实例。
	确保在批量插入时，每个目标节点都能获得独立的子节点/属性对象。
修复遗漏的本地化条目

API

TRYJUMPSTR stringVariable

TRYCJUMPSTR stringVariable
与 CALL、JUMP 及其 TRY 系统类似，但允许通过一个字符串表达式来指定完整的函数调用行（包括函数名和参数）。
与 CALLFORM 的区别在于：CALLFORM 的参数结构在编译时必须固定，而 CALLSTR 系列是在运行时解析整个字符串。这意味着可以动态地改变传递给函数的参数数量或类型。
该命令支持以下两种解析格式：
函数式写法："FUNC_NAME(ARG1, ARG2)"
逗号分隔写法："FUNC_NAME, ARG1, ARG2"
详细说明：
TRYCALLSTR / TRYJUMPSTR：如果字符串中指定的函数名不存在，程序不会报错，而是直接跳过执行。
TRYCCALLSTR / TRYCJUMPSTR：属于 TRYC 系统，如果指定的函数存在则执行；如果不存在，则执行随后的 CATCH 分句。
参数解析：字符串内的参数会根据当前的执行上下文进行解析。例如，如果字符串为 "MY_FUNC(LOCAL)"，则在执行时会读取当前函数内 LOCAL 变量的值。
Hint
仅作为语句（Statement）使用。
由于该命令涉及运行时的词法分析与语法解析，其执行效率略低于静态的 CALL 或 CALLFORM。在对性能要求极高的超大型循环中应谨慎使用。
字符串内的语法错误（如括号不匹配）将在运行时触发 CodeEE 报错。
接受INPUTS系指令的RESULTS作为参数时需要注意，由控制台输入的部分字符需要'\'转义，这就包括小括号。
Example
MAIN.ERB

@SYSTEM_TITLE
	#DIMS DYNAMIC COMMAND
	; 动态构造调用字符串
	COMMAND '= "TEST_FUNC" + "(100, 200)"
	CALLSTR COMMAND
	
	; 直接传递包含参数的字符串
	LOCALS = SHOW_STATUS, 1, "READY"
	TRYCALLSTR LOCALS

@TEST_FUNC(ARG:0, ARG:1)
	PRINTFORML 接收到的参数为: {ARG:0} 和 {ARG:1}

@SHOW_STATUS(ARG, ARGS)
	PRINTFORML ID:{ARG} 模式:%ARGS%

Result
接收到的参数为: 100 和 200
ID:1 模式:READY

==================================
EXISTVAR:
==================================
原版：

输入：string
返回：int
注释：

如果存在与 varName 同名的变量 / 常量则返回对应的正整数，否则返回 0。

为整数类型时，返回值 setbit 1
为字符串类型时，返回值 setbit 2
为常量类型时，返回值 setbit 3
为二维数组时，返回值 setbit 4
为三维数组时，返回值 setbit 5

命令 / 行内函数两种写法均有效。
==================================
改造：

输入：string,(int)
返回：int
注释：

如果存在第二输入变量，则将string所输入的变量视为一个具体的存储单元，判断是否存在，若存在返回1，不存在返回0
如果不存在第二输入变量，则按原版执行

命令 / 行内函数两种写法均有效。

例：

ERB代码：
PRINTFORML {EXISTVAR("CFLAG:0:0", 1)}
PRINTFORML {EXISTVAR("CFLAG")}
PRINTFORML {EXISTVAR("CFLAG:0:0")}

终端输出结果：
1
1
0

GETSOUNDORBGMINFO(新增):
==================================

读取SOUND通道或BGM通道的音频播放状态

输入：int, int(可省略)
返回：int
注释：

第一参数读取SOUND通道，第二参数读取所需的音频信息
音频信息总共有五种：音频总长度、当前播放进度、正在播放中、音频音量、音频速度
若第二参数存在，则1返回音频总长度、2返回当前播放进度、3返回正在播放中、4返回音频音量、5返回音频速度
返回值位于result:0中
若第二参数不存在，则同时返回所有信息，result:0返回音频总长度、result:1返回当前播放进度、result:2返回正在播放中、result:3返回音频音量、result:4返回音频速度

命令 / 行内函数两种写法均有效。

ISPLAYINGSOUND(新增):
==================================

判断SOUND通道是否正在播放

输入：int（可省略）
返回：int
注释：

输入一个参数以检查某个通道是否有音频正在播放，若正在播放，则返回通道编号，否则返回-1
省略参数的情况下将遍历所有通道，直到检测到正在播放的通道时返回通道编号，或者遍历完所有通道后返回-1

命令 / 行内函数两种写法均有效。

==================================
SOUNDCONTROL(新增):
==================================

控制SOUND通道的音频播放情况

输入：  ① int, int
		② int, int, int, int（可省略）
返回：int
注释：

情况①：第一参数为通道编号，第二参数为控制类型
控制类型总共有两种种：0为暂停，1为继续播放，2为停止

情况②：第一参数为通道编号，第二参数为变速操控编号（仅支持3），第三参数为变速倍率，第四参数为变速类型
若第四参数存在，则变速时音调会随速度改变
若不存在，这变速时音调不改变

以上两种情况下，若通道编号不存在，返回-1，若控制类型不存在，返回-2，若控制成功，返回1

命令 / 行内函数两种写法均有效。
